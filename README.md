# Impr3q Frontend - 3D Printing Quotation System

## Description

This project is a **minimalist and responsive frontend** for a distributed 3D printing quotation, order, and monitoring system. Built as a Single Page Application (SPA) using React, Vite, and Tailwind CSS, it allows you to simulate and visualize all main user and printer flows using mock data for interface and navigation testing.

---

## What can you see and test?

- **Login, registration, and password recovery** (choose between user or printer account during registration)
- **Product and material catalog navigation**
- **Shopping cart** (add, remove, modify products)
- **Quotation creation form** (with all required fields for order creation)
- **Quotation summary and confirmation**
- **Payment flow** (mock)
- **Order monitoring** (mock)
- **Messaging between user and printer** (mock)
- **Role-based navigation and menus** (user or printer)
- **Assigned orders view for printers**
- **Responsive design for desktop and mobile**

## Load Balancer Integration

To expose the frontend to the internet and distribute traffic efficiently and securely, you can use a **Load Balancer** (e.g., AWS Application Load Balancer, Nginx, HAProxy, etc.).

### Example with AWS ALB:
- **HTTP Listener (port 80):**
  - Routes incoming traffic to the target group where the frontend is deployed (e.g., EC2 or ECS instance running this frontend).
- **HTTPS Listener (port 443):**
  - (Optional) For secure traffic, configure an SSL certificate and redirect to HTTPS.
- **Rules:**
  - You can route `/api/*` to backend microservices and everything else to the frontend.

### Example with Nginx (local or VM):
```nginx
server {
    listen 80;
    server_name your-domain.com;

    root /var/www/frontend/dist; # Folder generated by Vite (npm run build)
    index index.html;

    location /api/ {
        proxy_pass https://api.otherdomain.com/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    location / {
        try_files $uri $uri/ /index.html;
    }
}
```
> **Note:** The Load Balancer must have a listener on port 80 (HTTP) or 443 (HTTPS) and route traffic to the frontend. If using AWS, configure the target group and routing rules according to your architecture.

## How to test the flows?

- **Login/Registration:** Use any email and password. Choose the account type (user or printer) during registration.
- **Navigation:** Use the sidebar menu to access catalog, cart, quotation, payments, messaging, orders (if printer), etc.
- **Cart:** Add products from the catalog, view the cart empty or with products.
- **Quotation:** Complete the form with customer data, notes, and review all items before submitting.
- **Role differentiation:**
  - **User:** See catalog, cart, quotation, payments, monitoring, messaging.
  - **Printer:** See assigned orders, messaging, clients, settings.
- **Mock:** All data and flows are simulated, no real backend connection.

## Swagger (API Documentation)

This frontend is ready to consume REST APIs documented with **Swagger/OpenAPI**. In a real environment, authentication, catalog, quotation, payment, order, and messaging endpoints would be documented and tested via Swagger UI, for example:

- **Users:** `/auth/login`, `/auth/register`, `/auth/profile`, `/auth/logout`, `/auth/forgot-password`
- **Catalog:** `/api/v1/productos`, `/api/v1/materiales`, `/api/v1/buscar`
- **Quotation:** `/quotations`, `/quotation_items`
- **Payments:** `/payments`, `/invoices`
- **Orders:** `/orders`, `/orders/:id/tracking`
- **Messaging:** `/messages`

> **Note:** This frontend does not expose Swagger, but is ready to consume any backend documented with it.
